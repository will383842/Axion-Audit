# 13. STRATÉGIE DE TESTS ET RECETTE — V2.2

- **Unitaires** (Vitest) : moteur d'assemblage du questionnaire (matrices d'étiquettes) · **scoring §32.1** (jeux de données de référence par type de réponse, résultats attendus figés, drapeaux rouges, complétude, roll-up pondéré) · **machine à états mission §32.2** (toutes les transitions, autorisées et interdites).
- **Intégration API** (Vitest + Postgres testcontainers) : RBAC exhaustif (chaque rôle × chaque route) · **propriété de session §9.9** (push croisé → `forbidden`) · idempotence du push (rejouer 3× le même lot = même état) · **unicité `answers(interview_id, mission_question_id)`** (re-réponse = révision) · webhooks signés + **anti-rejeu** (signature invalide, timestamp hors fenêtre, nonce rejoué → rejetés) · **garde-fou reset mot de passe** (outbox non vide → refus).
- **End-to-end** (Playwright) : parcours complet — création mission → génération questionnaire → sessions hors ligne (contexte offline) → coupures réseau simulées → sync → agrégation → export. **Les 8 scénarios §9.8 scriptés et marqués `@critique`** (jamais skippables). **Test export de secours : création hors ligne → restauration sur un 2e profil navigateur → données identiques.**
- **Fil rouge cumulatif (V2.11 — voir 09 §4bis)** : deux missions canoniques en fixtures dès L1 — **FIL-TPE** (micro, 8 pers., 1 entretien) et **FIL-GC** (grand compte fictif : arbre 150 unités / 4 niveaux, 60 sessions, ~8 000 réponses générées par script) ; un test `@filrouge` rejoue à chaque merge le parcours de bout en bout disponible à date, sur LES DEUX échelles ; toute porte l'exige vert. Le générateur de données FIL-GC est un outillage de test livré au L1.
- **Charge** (k6) : 50 clients qui poussent simultanément 1 000 ops chacun ; p95 < 500 ms hors jobs.
- **Sécurité** : ZAP baseline en CI ; revue OWASP ASVS niveau 2 avant la mission le client pilote ; tentatives d'accès financier avec un token consultant ; test de restauration de sauvegarde automatique chaque nuit (Postgres + MinIO).
- **Conformité schéma** : diff automatisé en CI entre le schéma Postgres réel et le fichier 04 (tout écart = build rouge).
- **Recette métier** : audit à blanc complet par Williams (2 entretiens + 1 observation fictifs, un en mode avion intégral), checklist §15.
