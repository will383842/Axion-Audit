# NOMS DE CLIENTS SURVEILLÉS PAR L'INVARIANT 2
#
# Copiez ce fichier en `docs/.clients-surveilles.txt` (gitignoré) et mettez-y les
# noms de vos clients réels, UN PAR LIGNE. `pnpm check:invariants` échouera si l'un
# d'eux apparaît dans le code — invariant 2 : « aucune référence client, tout ce qui
# varie est une donnée de mission ».
#
# Ce fichier-ci ne contient AUCUN nom réel : il est versionné, le dépôt est public.
# La vraie liste ne l'est jamais, et elle grandira avec vos clients.
#
# En CI, la liste arrive par le secret de dépôt AXION_CLIENTS_SURVEILLES
# (noms séparés par des virgules), lu par le job `invariants` de ci.yml.
#
# ATTENTION — ce fichier a longtemps affirmé cette phrase alors que LE CÂBLAGE
# N'EXISTAIT PAS. Relevé par le gardien A02 au lot L1 : la variable n'apparaissait
# nulle part dans .github/, et le contrôle sortait en 0 en annonçant « NON
# APPLIQUÉ ». L'invariant 2 — l'un des HUIT non négociables — n'a donc jamais été
# vérifié par la CI, y compris dans les runs annoncés tout verts.
#
# Le câblage existe désormais. Mais TANT QUE LE SECRET N'EST PAS CRÉÉ dans les
# réglages du dépôt (Settings → Secrets and variables → Actions), le job
# `invariants` ÉCHOUE — délibérément. Un contrôle qui n'a rien vérifié ne doit
# jamais sortir vert : c'est la règle appliquée partout ailleurs dans ce dépôt.
#
# Exemple de contenu attendu dans docs/.clients-surveilles.txt :
# ACME Industries
# Fromagerie du Val
